# office-request: 요청 구분과 비서실장에게 넘기기

이 스킬은 **프로그램 폴더**(이 파일 위쪽에 `dashboard/`·`package.json`이 있는 폴더)에서 연 세션 전용이다. 작업 공간 세션·대시보드 실행의 비서실장은 `office-task` 절차를 따른다. 기능의 정본은 `docs/SPEC.md`, 사용자 설명은 `README.md`·`GUIDE.html`이다. 이 문서와 다르면 정본을 따르고 이 문서를 고친다.

## 1. 먼저 구분한다: 누가 처리할 요청인가

| 요청 | 처리 | 예 |
| --- | --- | --- |
| 프로그램 운영 | **터미널 AI가 바로** | 서버 켜줘·꺼줘, 상태 확인, 처음 설치 점검(`npm run doctor`), 업데이트 |
| 조직 구성 | **터미널 AI가 바로** | "○○ 업무를 맡길 건데 부서·직원 세팅해줘", 회사 규칙·모델 변경, 세팅 되돌리기 |
| 프로그램 수정·기능 추가 | **터미널 AI가 개발** | 화면·버튼 고치기, 새 기능, 오류 원인 찾기 |
| 사용법·가능 여부 질문 | **터미널 AI가 답** | "예약은 어떻게 써?", "카페 댓글도 돼?" |
| 실제 사무 업무 | **비서실장에게 넘김**(`office-ask`) | 조사·보고서, 메일 발송, 카페·블로그 글, 댓글, 예약 업무, 지속 감시, 사이트 조회·업로드 |

- 운영·조직·개발 요청의 절차는 `AGENTS.md`의 "프로그램 레포에서 연 세션" 절을 따른다.
- **실제 사무 업무는 터미널 AI가 직접 하지 않는다.** 프로그램 폴더에서 웹 조사·메일 발송·글 게시를 직접 하면 대시보드의 안전선을 우회한다. 우회되는 것은 발송 전 확인, 메일 20통 제한, 첨부 원문 근거, 계정 파일 보호, 중복 발송 방지, 비서실장 검토, 결과 기록이다. 대신 아래 2의 순서로 비서실장에게 넘긴다. 대시보드 지시창에 넣은 것과 똑같이 처리된다.
- 둘이 섞인 요청(예: "직원 세팅하고 매일 카페 글 올려줘")은 터미널 일(세팅)을 먼저 끝내고 업무를 넘긴다.

## 2. 비서실장 업무를 받았을 때 하는 일

1. **서버 확인:** `npm run office:status`로 확인하고, 꺼져 있으면 켤지 묻지 않고 켠다(AGENTS.md 서버 켜기 절차).
2. **준비 점검:** 그 업무에 필요한 것을 확인하고, 빠진 것이 있으면 넣기 전에 짧게 안내한다.
   - 담당 부서·직원: 현재 구성(`node scripts/office.mjs org export <임시 파일>`)에 맞는 근무중 직원이 없으면 세팅을 제안한다.
   - 외부 작업(메일·글·댓글·사이트): 대시보드 **계정 연결**에 해당 계정이 있고 **처음 한 번 대표가 직접 로그인**했는지. 터미널 AI는 계정 파일(`보관함/계정.env`, `~/.config/ai-office/private`)을 읽지 않는다. 로그인이 안 됐으면 비서실장이 계정 필요 질문으로 멈추니, 대표에게 계정 연결 화면에서 로그인하라고 먼저 알려 준다.
   - 첨부 파일: 터미널 AI가 대신 찾거나 열지 않는다. 비서실장(실행기)이 찾고, 못 찾으면 묻는다.
3. **넣을 문장 확정(원문 보존):** 아래 "원문 그대로 넣기"를 지켜 넣을 문장을 정하고, 넣기 전에 한 줄로 보여 준다(예: `넣을 지시: "매일 오전 9시에 https://cafe.naver.com/○○ 자유게시판에 ○○ 주제 글 1개 올려줘"`). 대표가 이미 그대로 넣으라고 했으면 바로 넣는다.
4. **넣기:** `node scripts/office-ask.mjs ask '<지시문>'`(작은따옴표 안의 작은따옴표는 피한다). 출력의 실행 id·예약 등록·일시정지 여부를 대표에게 전한다.
5. **진행·질문 전달:** `node scripts/office-ask.mjs wait <실행 id>`로 끝나거나 답변이 필요할 때까지 기다린다(기본 600초, 긴 업무는 `--timeout`으로 늘리거나 백그라운드 실행).
   - **답변 필요**면 비서실장 질문을 대표에게 그대로 보여 주고 답을 받는다. 터미널 AI가 대신 결정하지 않는다. 특히 "실행할까요?", "남은 메일 발송할까요?", 첨부 후보 선택은 반드시 대표 답을 받는다.
   - 대표 답은 `node scripts/office-ask.mjs reply <실행 id> '<대표 답>'`으로 넣는다. 답도 원문 그대로 넣는다.
   - **끝남**이면 마지막 답변(보고서 요약)을 전하고, 결과 파일은 대시보드 완료 창이나 `보관함/최종산출물/`에서 보라고 안내한다.
6. 대표가 대시보드 화면에서 직접 지시·답장해도 된다. 같은 업무로 이어진다. `node scripts/office-ask.mjs status`로 최근 업무를 볼 수 있다.
7. `office-ask`는 대시보드가 실행한 AI(비서실장·직원) 안에서는 거부된다. 그 안에서 새 지시를 만들지 않는다.

### 원문 그대로 넣기

비서실장은 들어온 지시 원문으로 권한을 판단한다(발송·게시·업로드 허용, "끝까지 자동으로" 위임, 첨부 파일 이름, 예약·감시 여부). 터미널 AI가 다듬다가 대표가 하지 않은 말을 넣으면 그 권한이 생긴다.

- 대표가 한 문장을 **그대로** 넣는 것이 기본이다. 덧붙일 수 있는 것은 확인한 사실뿐이다(대표가 말한 카페의 정확한 주소, 수량, 담당 부서 이름).
- 다음 표현은 **대표가 직접 말한 경우에만** 넣는다: 보내/발송/게시/올려/등록/업로드/댓글 달아, "끝까지 자동으로"·"확인 없이"·"알아서", 첨부 파일 이름, "매일·○시에·계속·멈출 때까지".
- 대표가 "초안", "문안만", "보내지 말고"라고 했으면 그 표현을 빼지 않는다.
- 대표 말이 모호해 권한 표현이 필요한지 애매하면 넣지 말고 물어본다(예: "글을 실제로 올릴까요, 초안만 만들까요?").
- 답장도 같다. 대표가 "응"이라고 했으면 질문에 맞는 대표의 뜻을 바꾸지 말고 `진행`처럼 대표가 고른 답만 넣는다.

## 3. 지시문 쓰는 법

대표의 말에 아래 요소가 빠져 결과가 흔들릴 것 같으면 **대표에게 물어 채운다**(대신 지어내지 않는다). 한 지시에 **한 가지 목표**만 담는다.

- **무엇을:** 목표와 수량(예: 업체 10곳, 글 2개)
- **어디서·누구에게:** 조사 범위, 카페·게시판 주소, 사이트 링크, 수신 대상(공개 제휴 문의 창구)
- **누가(선택):** 담당 부서·직원("마케팅이 조사하고 최대리가 HTML 작성"). 비우면 비서실장이 회의로 정한다
- **결과 형식(선택):** 엑셀·HTML 보고서·표, 저장 위치(전체 경로, 비우면 `보관함/최종산출물/날짜/`)
- **밖으로 나가는지:** 메일 발송·게시·업로드를 할지, 문안까지만 할지("초안만"). 실행 직전 확인을 건너뛰려면 "끝까지 자동으로"
- **언제:** 한 번("내일 오전 10시에"), 정한 횟수("내일부터 3일간 매일 9시에"), 매일("매일 오전 9시에"), 계속 감시("새 글이 올라오면 계속 … 멈출 때까지 / 24시간 동안")
- **첨부(메일):** 파일 이름이나 경로("제휴제안서.pdf 첨부해서")

## 4. 기능별 지시 예시와 지켜야 할 점

| 업무 | 지시 예시 | 지켜야 할 점 |
| --- | --- | --- |
| 조사·보고서 | 경쟁사 3곳 가격 정책을 조사해서 비교표가 있는 HTML 보고서로 만들어줘 | 출처·기준일이 보고서에 남는다. 숫자는 원본과 대조하라고 덧붙이면 좋다 |
| 담당 지정 | 리서치부가 조사하고 문서제작부 최대리가 HTML로 정리해줘 | 근무중 직원만 배정된다 |
| 저장 위치 | … 엑셀로 정리해서 ~/Desktop/상담사 리스트 폴더에 저장해줘 | 전체 경로로 쓴다 |
| 카페·블로그 글 | https://cafe.naver.com/○○ 자유게시판에 ○○ 주제로 소개 글 1개 올려줘 | 계정 연결·첫 로그인 필요. 게시판 주소를 적는다. 지원: 네이버 블로그·카페, 다음 카페, 티스토리, 브런치 |
| 댓글 | (글 주소)에 ○○ 내용으로 댓글 달아줘 | 대상 글 주소가 필요하다 |
| 예약 | 매일 오전 9시에 ○○ 주제 유튜브 숏츠를 찾아 (카페 게시판 주소)에 2~3개씩 소개 글을 올려줘 | PC·서버가 켜져 있어야 한다. 놓친 시각은 몰아서 실행하지 않는다. 같은 영상은 다시 올리지 않는다. 영상과 장소·정보 글을 섞으려면 개수를 따로 적는다(예: "숏츠 2개와 애견 동반 핫플 1개"). 장소 중복은 코드가 막지 않으니 이미 올린 장소를 지시에 적는다. 예약 업무의 메일·글은 실행 전 확인 없이 진행된다 |
| 지속 감시 | (사이트 주소) 새 공지가 올라오면 계속 요약해서 운영팀에 전달해줘. 오늘 18시까지 | 기본 5분 간격. 중지 버튼이나 "중지" 답장으로 끝낸다 |
| 사이트 조회 | (ERP 링크)에서 30일 넘게 활동 없는 상담사를 찾아 엑셀로 정리해줘 | 일반 웹사이트로 계정 연결. 조회는 읽기 전용 |
| 사이트 작업 | 만든 HTML을 (관리자 화면 링크)의 제휴 페이지에 업로드해줘 | 첨부는 그 업무 산출물만. 삭제·결제·계정 변경은 하지 않는다 |
| 제휴 메일 | 서울 소재 대학 창업동아리 10곳을 조사해서 공개된 제휴 문의 메일로 제휴 제안 메일 보내줘. 제휴제안서.pdf 첨부해서 | 네이버웍스 메일만. 업체별 개별 발송. **20통마다 "남은 메일 발송할까요?"**(위임해도). 첨부는 이름만 써도 찾지만 여러 개·못 찾음이면 먼저 묻는다. 모든 수신자에게 같은 첨부 |
| 일시정지·재개 | 하던 작업 멈추고 정리해 둬, 다음에 이어서 하자 / 이어서 해줘 | 중지 버튼으로 멈춘 업무는 재개하지 않는다 |

**지원하지 않거나 주의할 것:** 문자(SMS) 발송, 송금·결제·세금 신고·계약·삭제·탈퇴는 하지 않는다. 메일 주소는 공개된 제휴 문의 창구만 쓰고 자동 수집하지 않는다(정보통신망법상 이메일 무단 수집 금지·광고성 메일 사전 동의. 법적 판단은 전문가 확인 권장). 업체마다 다른 첨부는 업무를 나눈다. 구글 시트 전용 연결은 없다. 링크 보기 공개 주소를 주거나 xlsx·csv로 내려받아 보관함에 두고 경로를 적게 한다. 새 업무로 다시 지시하면 이전 메일 발송 기록이 이어지지 않으니 보낸 곳 목록을 제외하라고 적게 한다.

## 5. 지시문 알잘딱깔센 점검

넣기 전에 확인하고, 덧붙이거나 물어본 점이 있으면 한 줄로 알린다. 점수표나 형식적 질문은 만들지 않는다.

- **알아서:** 대표의 목적을 한 문장으로 잡는다. 확인한 사실(현재 조직·계정·기능)과 가정을 구분한다. 지금 기능으로 안 되는 부분은 숨기지 않고 대안을 준다.
- **잘:** 실패하기 쉬운 곳을 미리 막는다. 계정 연결·첫 로그인, 게시판·사이트 주소, 첨부 파일 위치, 20통 단위 확인, 예약 시 PC·서버 켜짐, 법적 주의가 그런 곳이다.
- **딱:** 대표가 말한 범위·수량·기한만 넣는다. 말하지 않은 발송·게시·업로드·위임을 넣지 않는다(원문 그대로 넣기). 외부 작업이 처음이면 "초안만"부터 권하되, 대표가 고르게 한다.
- **깔끔:** 짧은 문장 한두 개로 쓴다. 담당·형식·저장 위치는 필요할 때만 쓴다.
- **센스:** 결과를 어떻게 받는지(형식·위치)와 확인 방법을 함께 알려 준다. AI 사용량이 큰 업무(대량 조사·지속 감시)는 업무 예산(기본 40회·60분)을 안내한다.

대표가 "알아서" 맡겨도 권한 표현은 대표 원문에 있는 것만 쓴다. 범위·형식 같은 나머지는 권장 기본값으로 채우고 `가정:`으로 한 줄씩 밝힌다. 질문은 외부 발송 대상·비용·법적 판단처럼 대표만 정할 수 있는 것만 한 번에 묶는다.
